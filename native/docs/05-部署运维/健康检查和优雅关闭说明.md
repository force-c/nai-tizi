# 健康检查与优雅关闭

## 接口

- `GET /health/startup`：启动探针，确认应用初始化完成。
- `GET /health/live`：存活探针，只判断进程是否可服务。
- `GET /health/ready`：就绪探针，检查 PostgreSQL、Redis 等关键依赖。
- `GET /health`：人工查看的基础健康信息。

服务端口默认 `9009`。

```bash
curl http://127.0.0.1:9009/health/startup
curl http://127.0.0.1:9009/health/live
curl http://127.0.0.1:9009/health/ready
```

## 关闭顺序

进程收到 SIGINT/SIGTERM 后停止接收新请求，等待 HTTP 请求退出，再关闭操作日志写入器、后台组件、Redis 与数据库连接。Kubernetes 的 `terminationGracePeriodSeconds` 应大于应用的 HTTP shutdown 超时。

不要让 liveness 探针依赖外部服务，否则 PostgreSQL 或 Redis 的短暂故障会造成无意义的容器重启；依赖状态属于 readiness。
