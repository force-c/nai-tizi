# 部署说明

## 配置文件

应用通过环境变量 `ADCS_APP_ENV` 选择 `conf.{env}.yaml`，默认使用开发环境配置。程序会优先在当前工作目录查找配置文件，其次查找可执行文件所在目录。

```bash
export ADCS_APP_ENV=prod
./quick-admin
```

建议的生产目录：

```text
/opt/quick-admin/
├── quick-admin
├── conf.prod.yaml
└── logs/
```

## 构建和部署

```bash
go build -o build/quick-admin ./cmd/api
cp cmd/api/conf.prod.yaml build/
```

容器镜像使用仓库的 `dockerfile/Dockerfile` 构建。运行前需保证 PostgreSQL 和 Redis 配置可连接。

## 自动数据库迁移

服务初始化数据库连接后会自动执行 Goose migration，不需要单独运行迁移命令。迁移文件通过 Go embed 编入二进制，部署时无需复制 SQL 文件。

- 迁移目录：`internal/database/migrations/sql/`
- 版本表：`goose_db_version`
- 迁移失败：服务启动失败，避免在未知数据库结构上继续运行。

当前工程仍保留 GORM `AutoMigrate` 用于创建基础业务表，随后执行 Goose 版本化迁移。

## 启动验证

正常启动日志应包含：

```text
database auto migration completed
starting goose database migrations...
goose database migrations completed
container initialized successfully
```

启动后检查健康接口：

```bash
curl http://127.0.0.1:9009/health
curl http://127.0.0.1:9009/ready
```

## 常见问题

配置文件找不到时，检查 `ADCS_APP_ENV`、工作目录和 `conf.{env}.yaml` 文件名。数据库迁移失败时，优先检查 PostgreSQL 连通性、账号 DDL/DML 权限和迁移日志；修复后重新启动即可。
