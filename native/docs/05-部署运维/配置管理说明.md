# 配置管理说明

## 设计原则

应用配置使用强类型 `config.Config`，统一从 YAML 和环境变量加载。业务代码不得直接读取 Viper，也不得使用字符串 key 获取配置。

加载顺序：

1. 代码默认值
2. `conf.dev.yaml` 或 `conf.prod.yaml`
3. 明确绑定的 `QUICK_ADMIN_*` 环境变量
4. 强类型反序列化与启动校验

`QUICK_ADMIN_APP_ENV` 仅选择配置文件，配置结构本身没有 `Env` 字段。

## 环境变量命名

YAML 层级和驼峰字段转为大写下划线：

| YAML | 环境变量 |
| --- | --- |
| `server.port` | `QUICK_ADMIN_SERVER_PORT` |
| `database.dsn` | `QUICK_ADMIN_DATABASE_DSN` |
| `database.maxOpenConns` | `QUICK_ADMIN_DATABASE_MAX_OPEN_CONNS` |
| `redis.password` | `QUICK_ADMIN_REDIS_PASSWORD` |
| `jwt.secret` | `QUICK_ADMIN_JWT_SECRET` |
| `wechat.appId` | `QUICK_ADMIN_WECHAT_APP_ID` |
| `wechat.secret` | `QUICK_ADMIN_WECHAT_SECRET` |

完整示例见 `native/.env.example`。

## 开发与生产密钥规则

`conf.dev.yaml` 可以保存仅供本机使用的开发数据库、Redis 和 JWT 参数，方便直接启动。开发密钥不得复用于任何生产环境。

`conf.prod.yaml` 的密钥字段必须保持为空。数据库密码、Redis 密码、JWT、微信、短信、邮件和对象存储密钥由部署平台通过 Secret 注入。

生产配置要求：

- `jwt.secret` 至少 32 字符
- PostgreSQL DSN 和 Redis 地址不能为空
- 启用第三方能力时，其必需参数必须完整
- CORS 必须关闭

项目不识别旧配置名或旧环境变量；配置变更直接更新强类型结构、YAML、环境变量绑定、示例和测试。
